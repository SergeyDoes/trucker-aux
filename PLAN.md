# Spatial Cab Audio — план

Любое приложение (VLC, браузер, Spotify) → VB-Audio Virtual Cable → наше приложение `spatialcab-audio.exe`. Оно рендерит бинаурал: музыка звучит из «динамиков в дверях», а сцена поворачивается вслед за головой водителя в ATS/ETS2. Звук самой игры идёт мимо цепочки, напрямую в наушники.

## Архитектура

```
ATS/ETS2 ──► spatialcab.dll (SCS Telemetry SDK plugin, минимальный)
                 │  OSC/UDP 127.0.0.1:<port>   /ypr (градусы), /active
                 ▼
VLC/браузер ─► VB-Cable ─────► spatialcab-audio.exe ─────────────────► наушники
                                 WASAPI capture
                                 → кольцевой буфер + компенсация дрейфа
                                 → HRTF: 2 виртуальных динамика, повёрнутые по голове
                                 → WASAPI render
Звук игры ──────────────────────────────────────────────────────────► наушники
```

- Плагин минимальный: читает `truck.head.offset`, переводит в градусы и шлёт OSC. Вся логика (сглаживание, нейтраль, инверсии, раскладка динамиков) живёт в аудиоприложении. DLL перезагружается только через консоль игры (`sdk reload`), а приложение можно перезапускать и настраивать как угодно, не трогая ATS.
- Звук обрабатывается в отдельном процессе, не внутри DLL: если аудио упадёт или зависнет, игра не пострадает.
- OSC оставляем как протокол. Формат тривиальный, кодируем вручную. Тот же поток `/ypr` понимает SPARTA Binauraliser, так что он остаётся запасным вариантом и эталоном для сравнения на слух.

## Что уже известно (разведка)

- В RadioStation 3D ставится `RadioStation.dll`, это доработанный `examples/telemetry_position` из SCS SDK. Каналы: `truck.world.placement`, `truck.cabin.offset`, `truck.head.offset`. Шлёт текстовые UDP на `127.0.0.1` в формате `%d;%.3f×9`, порт 3007 или 5005. Чисел 9, а у трёх placement их 18, значит DLL что-то сворачивает (возможно, в мировые координаты).
- Нам нужен `truck.head.offset`, тип **`fplacement`** (не `dplacement`): смещение позиции и ориентации головы в пространстве кабины относительно положения по умолчанию. Динамики закреплены на кабине, поэтому ориентация слушателя относительно кабины и есть head.offset. `cabin.offset` (качание кабины, тоже `fplacement`) для звука почти не важен.
- **Углы в SCS SDK измеряются в оборотах, а не в радианах:** heading 0.25 = 90°. Heading лежит в [0,1) (проверено по `scssdk_value.h`), отсчёт против часовой, 0.25 = влево. Значит, лёгкий поворот вправо приходит как 0.99, то есть 356°, а не −4°. Приводить к −180..180 обязательно, в том числе при сглаживании. Pitch в [−0.25, 0.25] (вверх положительно), roll в [−0.5, 0.5]. Реальный знак поворота головы подтвердить в R0.
- **Трекера головы нет, камера крутится мышью.** Весь проект держится на допущении 1: если head.offset не видит поворот мышью, подход не работает. Поэтому R0 идёт первым.
- `third_party/scs-sdk-plugin` (RenCloud, MIT) склонирован и собирается в VS2022 (`scs-telemetry/vs2012/scs-telemetry.vcxproj`, Release x64; в `.sln` нет конфигурации x64, собирать проект напрямую). Проверки версии игры в нём нет. Он пишет всю телеметрию в общую память `Local\SCSTelemetry`: head.offset по смещению 2024 (6 float: x y z heading pitch roll, обороты как в SDK), cabin.offset по смещению 2000, флаг паузы по смещению 4. Каналы регистрируются с `no_value`, но NULL он игнорирует: при пропаже значения в памяти остаётся последнее.
- Заголовки SCS SDK лежат в `third_party/scs-sdk-plugin/scs_sdk/include` под лицензией MIT, их можно коммитить.
- В SDK есть консольные команды `sdk reinit`, `sdk unload`, `sdk reload`: DLL можно пересобрать и перезагрузить без перезапуска игры.
- В системе установлен VB-Audio Virtual Cable (не VAC Muzychenko). Плеер выводит на `CABLE Input`, приложение захватывает с `CABLE Output`. Наушники — `Наушники (Logitech PRO X Gaming Headset)`, USB.
- У кабеля и наушников разные тактовые генераторы. Без компенсации дрейфа буфер между захватом и выводом за минуты переполнится или опустеет, и пойдут щелчки. Компенсация обязательна.
- Light Host соединяет плагины только каналами 0–1, поэтому цепочка IEM (Ambisonics, от 4 каналов) в нём не работает. SPARTA Binauraliser (стерео на входе, бинаурал на выходе, поворот по OSC `/ypr` в градусах) работает в любом стерео-хосте: годится для быстрой проверки на слух.

## Вехи

Порядок: R0 (дёшево и может закрыть проект), потом звук с `fake_telemetry.py`, потом свой код для игры. Отладка звука не должна зависеть от запуска ATS.

### R0 — разведка в игре (без своего C++)
- Собрать `third_party/scs-sdk-plugin` и положить `scs-telemetry.dll` в `<game>\bin\win_x64\plugins\` (игра покажет окно «advanced SDK features», это нормально).
- `py tools/shm_probe.py --csv docs/probe.csv`: крутим камеру мышью, переключаем внешние камеры, ставим паузу, выходим в меню. Записать в `docs/findings.md`, какие поля как меняются, знак yaw, что на внешних камерах.
- Закрывает допущения 1 и 2. Если head.offset не реагирует на мышь, останавливаемся и пересматриваем подход.

### A0 — проверка на слух (без кода)
- `CABLE Output` → любой простой хост (Light Host годится, плагину нужно только стерео) → SPARTA Binauraliser: 2 входа на ±30° по азимуту, чуть ниже ушей, OSC-приёмник включён.
- `tools/shm_to_osc.py` шлёт `/ypr` прямо из игры (общая память → OSC, порт 9000, на паузе ноль). Слушаем в ATS: убедительно ли звучит, в какую сторону уходит сцена.
- Щелчки раз в несколько минут здесь, скорее всего, вызваны дрейфом тактов в хосте. Это не повод бросать идею.
- Итог: решение, работает ли идея, эталон звучания для нашего рендера и стартовые углы динамиков.

### A1 — аудиоскелет: захват → вывод
- C++, CMake, MSVC x64, консольное приложение.
- WASAPI shared, event-driven. Захват с устройства, найденного по подстроке имени из ini (`CABLE Output`); вывод на устройство по умолчанию или по подстроке. Формат 48 кГц float, `CABLE Input` и `CABLE Output` в настройках звука Windows тоже выставить на 48 кГц.
- Между потоками захвата и вывода кольцевой буфер. Компенсация дрейфа: адаптивный ресемплер (libsamplerate или speexdsp), коэффициент подстраивается ПИ-регулятором по заполненности буфера (цель ~20 мс).
- Аудиопотоки с MMCSS (`AvSetMmThreadCharacteristics("Pro Audio")`).
- Проверка: passthrough работает час без щелчков, заполненность буфера стабильна. Коэффициент ресемплинга держится в пределах сотен ppm от 1.0 (лог раз в 10 с).

### A2 — бинауральный рендер
- HRTF-движок: Steam Audio (C API, Apache-2.0, встроенный HRTF плюс загрузка SOFA, билинейная интерполяция направлений). Каналы L и R идут как два моно-источника в два `IPLBinauralEffect`, результаты суммируются. Запасной вариант: libmysofa и свой FIR (4 свёртки по ~256 тапов, для CPU это копейки), но тогда интерполяцию и кроссфейд HRIR придётся писать самим.
- Направление на источник в системе координат головы: вектор динамика в кабине, повёрнутый обратно на (yaw, pitch, roll) головы. Координаты Steam Audio: −Z вперёд, +X вправо, +Y вверх.
- OSC-приёмник работает в отдельном потоке и принимает `/ypr` и `/active`. Аудиопоток читает последнюю позу атомарно, без блокировок.
- Сглаживание здесь: one-pole по углам с учётом перехода через ±180°, τ ≈ 20–30 мс. Игра уже сглаживает мышь, лишняя задержка портит ощущение. Если пришёл `/active 0` или OSC молчит дольше 1 с, плавно уходим в нейтраль (0,0,0).
- `spatialcab-audio.ini`: устройства, раскладка динамиков (азимут, возвышение, усиление), ширина стерео (M/S перед HRTF: виртуальные динамики слышны обоими ушами, и разделение каналов падает), HRTF (встроенный или путь к `.sofa`), порт, τ, инверсии осей.
- Проверка: `fake_telemetry.py` плавно вращает сцену, на слух не хуже SPARTA из A0.

> Развилка перед M1: вместо своей DLL аудиоприложение может читать `Local\SCSTelemetry` напрямую (опрос ~250 Гц), и тогда M1–M2 не нужны. Минусы: зависимость от чужого плагина, нет сигнала «значения нет», чтение всей структуры ради шести float. Решаем после R0 и A2.

### M1 — скелет плагина
- CMake + MSVC x64, заголовки SDK из `third_party/scs-sdk-plugin/scs_sdk/include`.
- `scs_telemetry_init` / `scs_telemetry_shutdown`. Регистрация `truck.head.offset` и `truck.cabin.offset` как `fplacement` с флагом `SCS_TELEMETRY_CHANNEL_FLAG_no_value`: NULL в колбэке означает, что значения нет. По умолчанию колбэк зовётся только при изменении, поэтому храним последнее значение. События `frame_end`, `paused`, `started`, конфиг `truck` (бренд и модель для пресетов).
- Логирование через `scs_log` и опционально в файл.
- Проверка: плагин грузится в ATS, в `game.log.txt` есть наши строки. Для итераций используем `sdk unload` / `sdk reload` в консоли.

### M2 — отправка OSC
- Неблокирующий UDP-сокет (Winsock, `WSAStartup` в `scs_telemetry_init`, не в `DllMain`), отправка на `frame_end` с ограничением частоты (≤ 100 Гц).
- Сообщения: `/ypr ,fff` одним пакетом (градусы, −180..180) и `/active ,i` (0 на паузе и при NULL из `no_value`; внешнюю камеру отличить нельзя). Ручная сборка OSC: адрес и строка типов с выравниванием до 4 байт, float big-endian. Unit-тест на кодирование.
- Конфиг `spatialcab.ini` рядом с DLL (путь через `GetModuleHandleExW(FROM_ADDRESS)` + `GetModuleFileNameW`): хост и список портов. Второй порт нужен как зеркало для `osc_monitor.py`, потому что два процесса не могут слушать один порт.
- Инверсии, сглаживание и нейтраль сюда не кладём, они живут в аудиоприложении.

### M3 — калибровка в игре
- `docs/audio-setup.md`: VB-Cable на 48 кГц, плеер направлен на `CABLE Input` через «Параметры → Громкость приложений», запуск `spatialcab-audio.exe`, описание ini.
- Калибровка: голова прямо, значит звук по центру; поворот влево, значит сцена уходит вправо. Если наоборот, инвертировать в ini приложения. В SDK heading положителен влево, как азимут в Steam Audio, так что инверсия, скорее всего, не понадобится.
- Раскладку динамиков подобрать на слух под «динамики в дверях». Опционально: конволюционная реверберация с IR салона после HRTF.
- Проверка: час езды без щелчков и без растущей задержки.

### M4 — полировка
- Параллакс: динамики как точки в кабине, направление и громкость считаются от реальной позиции головы из head.offset (игра сдвигает голову до 0.8 м при обзоре, см. `docs/findings.md`).
- Пресеты раскладки по бренду и модели тягача: плагин шлёт `/truck ,ss` из конфига `truck`, приложение выбирает пресет.
- Переподключение устройств: при `AUDCLNT_E_DEVICE_INVALIDATED` (выдернули наушники, сменилось устройство по умолчанию) переоткрыть поток.
- Иконка в трее, автозапуск.

### M5 — упаковка
- Сборка Release. Плагин кладётся в `<game>\bin\win_x64\plugins\`, приложение с ini — в любую папку.
- Совместимость с чужими плагинами в той же папке (`RadioStation.dll`, `fatigue_drift.dll`, `scs-telemetry.dll`): наш порт не 3007 и не 5005.

```
  src/config.*     чтение ini

  src/main.cpp
  src/audio_io.*   WASAPI capture/render, выбор устройств
  src/drift.*      кольцевой буфер + адаптивный ресемплер
  src/renderer.*   Steam Audio, виртуальные динамики

  src/config.*

  audio-setup.md
```

## Правила для реализации

- Плагин: никаких блокирующих вызовов в колбэках SDK (они идут в игровом потоке), никаких аллокаций в `frame_end`, буфер OSC статический. Любая ошибка сети молча игнорируется (с одним предупреждением в лог), игра не должна пострадать.
- Аудиоприложение: в аудиопотоках никаких аллокаций, мьютексов и файлового ввода-вывода. Поза головы передаётся из OSC-потока атомарно.
- Сначала звук (A0–A2) с `fake_telemetry.py`, потом игра.
