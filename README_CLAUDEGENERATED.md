# Trucker AUX

Car audio for American Truck Simulator and Euro Truck Simulator 2, in your headphones.
Your music plays from virtual speakers placed in the cab. When you look around in the
game, the speakers stay where they are, as real door speakers would.

> This README was generated by Claude (Anthropic) from the project's code and notes.
> The design notes are in [PLAN.md](PLAN.md), [docs/findings.md](docs/findings.md) and
> [the spec](docs/superpowers/specs/2026-09-30-speaker-editor-design.md).

## How it works

```
ATS/ETS2 ─► scs-telemetry.dll (RenCloud) ─► shared memory Local\SCSTelemetry
                                                   │ read at ~100 Hz (koffi)
┌──────────────────── Trucker AUX (Electron) ──────┼──────────────────────────┐
│ main: head pose, data folder, IPC                ▼                          │
│ input device ─(getUserMedia)─► AudioContext → M/S width                     │
│                                 → per speaker: filter → level → HRTF ─────────► headphones
│                                 AudioListener ← head pose                   │
│ panel: devices, presets, speakers                                           │
└─────────────────────────────────────────────────────────────────────────────┘
Player ─► CABLE Input (VB-Cable)                 Game audio ────────────────────► headphones
```

- Any player (browser, Spotify, VLC) plays into a virtual cable, VB-Audio Virtual Cable.
  Trucker AUX records the cable's other end.
- Each virtual speaker is a Web Audio HRTF panner placed in the cab. The listener turns
  and moves with the driver's head, read from the game's telemetry (`head.offset`).
- The game's own sound goes straight to the headphones, outside this chain.

## Features

- **Speakers:** up to 16 per preset. Each speaker has a channel (left, right or mono)
  and a level. Mirrored pairs keep the left and right speaker symmetric.
- **Speaker types,** with Linkwitz–Riley crossovers that sum flat where two types meet:

  | type | band |
  |---|---|
  | full range | no filter |
  | small full range | from 120 Hz |
  | tweeter | from 2.5 kHz |
  | midrange | 500 Hz – 2.5 kHz |
  | midbass | 60 – 500 Hz |
  | subwoofer | up to 120 Hz |

- **Stereo width:** from mono, through as recorded, to extra wide.
- **Editor:** a top view and a side view (SVG) and a 3D overview (three.js). Drag
  speakers and walls, select several with Ctrl+click or a box, copy and paste, also
  between presets, and nudge with the arrow keys.
- **Presets per vehicle:**
  - a preset applies to a model, to one of its chassis (told apart by the fifth-wheel
    position), or to a single vehicle by its plate;
  - Auto plays the narrowest preset that exists;
  - a card under the preset list shows what plays, what it applies to and what can be
    changed;
  - presets made by hand stay where you pick them.
- **Real head position:** the driver sits left of the vehicle's centre line by what the
  game reports. The game's seat adjustment moves the listener too.
- **Loudness matching:** a preset with many speakers is not louder than the default two
  doors. The trim is measured: K-weighted pink noise rendered through the engine.
- **Like a car radio:**
  - "Mute when" mutes the music while the engine or the electrics are off;
  - "Pause behavior" sets what happens on pause: always active, always muted, or by
    the vehicle's state.
- **Game camera:** the game's "look into turns" and "look toward the blinker" turn the
  camera, but the telemetry doesn't report them. Set the same options in the app and
  the sound turns with the camera.
- **Safe with the game:**
  - the shared memory is only opened for reading, never created;
  - the app does not read or change the game's files;
  - no sign-ins, no network.

## Requirements

- Windows 10 or 11.
- American Truck Simulator or Euro Truck Simulator 2.
- [RenCloud's scs-sdk-plugin](https://github.com/RenCloud/scs-sdk-plugin) (included as
  a submodule).
- [VB-Audio Virtual Cable](https://vb-audio.com/Cable/).
- Node.js and npm. Developed with Node 24 and Electron 44.
- Plain stereo headphones. Virtual surround (DTS Headphone:X, Windows Sonic, Dolby
  Atmos) would virtualize the binaural output a second time.

## Setup

1. Clone with the submodule:

   ```bash
   git clone --recursive <this repository>
   ```

2. Build the telemetry plugin in Visual Studio 2022:
   - open `third_party/scs-sdk-plugin/scs-telemetry/vs2012/scs-telemetry.vcxproj` and
     build Release x64 (the `.sln` has no x64 configuration, so build the project);
   - copy `scs-telemetry.dll` to `<game>\bin\win_x64\plugins\`;
   - on start the game asks about "advanced SDK features": accept.

3. Set up the audio:
   - route your player to `CABLE Input`;
   - in the VB-Cable control panel set Max Latency to 7168 and Internal SR to the rate
     you use;
   - use one sample rate everywhere: `CABLE Input`, `CABLE Output`, VB-Cable's Internal
     SR and the headphones. Any mismatch causes dropouts.

4. Install and start:

   ```bash
   cd app
   npm install
   npm start
   ```

5. In the panel, set Input to `CABLE Output` and Output to your headphones. Then set
   "Game camera" as in the game's Accessibility options.

## Using it

- **Coordinates:**
  - X goes right from the vehicle's centre line;
  - Y goes up and Z goes back, from the driver's default head;
  - the "0" in the views is that point.
- **Bounds** only frame the views for placing speakers; they don't change the sound.
- **Shortcuts,** outside text fields:
  - arrows nudge the selected speakers, Shift+arrows by 10 cm;
  - Delete removes them, Esc clears the selection;
  - Ctrl+A, Ctrl+C, Ctrl+V and Ctrl+D select all, copy, paste and duplicate.
- **Data** is kept next to the app, not in `%APPDATA%`:
  - `app/data/layouts.json`: the presets. The file in the repository is the author's
    set, as an example;
  - `app/data/settings.json`: devices and options;
  - `app/data/profile/`: Chromium's profile.

## Development

```bash
cd app
npm test             # unit tests (node --test)
npm run test:engine  # renders the audio graph offline and checks it in dB
```

- `tools/fake_shm.py` fakes the telemetry for work without the game. It takes a truck,
  a fifth-wheel position, a plate and a blinker. Run it only while the game is closed.
- `tools/cable_tone.py` and `tools/cable_check.py` check the virtual cable for dropouts.
- `tools/shm_probe.py` and `tools/shm_to_osc.py` are from the first experiments.

```
app/                        Electron app
  src/main/                 window, IPC, data folder, shared-memory reader
  src/shared/               pure logic: pose, layouts, presets, DSP, settings, devices
  src/renderer/             audio engine, views, 3D overview, panel
  test/                     unit tests
  scripts/                  engine check
third_party/scs-sdk-plugin  RenCloud's telemetry plugin (submodule)
tools/                      Python helpers
docs/                       findings from the game, specs and plans
```

## Limitations

- Windows only.
- External cameras can't be detected: the telemetry keeps the last head pose.
- The game doesn't report its camera options or the cab's size, so they are set by hand.
